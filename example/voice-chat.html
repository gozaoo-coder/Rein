链路、数据模型与渲染约定

  • 麦克风 → 200ms PCM 包 → Rust：16k/16bit/mono；Rust gzip 组帧发 WS；utterances 事件回流，definite 句立即 append 落库（含 start/end 毫秒）。
  • 3 分钟自动整理：runtime 计时窗口，满 3:00 把已转写句子结算为一段（消息+纪要请求），录音/WS 不中断；段间靠 sequence 与时间戳无缝衔接。
  • 纪要数据模型（voice_memos）：{id, chatId, messageId, title(自动生成), audioPath, durationMs, sentences:[{idx,text,startMs,endMs}], summary:[{kind,text,refs:[idx], md}]} —— 角标=refs、点句 seek=startMs、重放=audioPath。
  • Markdown 渲染约定：存储存原文、渲染时 parse；流式按块增量（完成块缓存为静态 HTML，仅末尾未完块重渲；未闭合代码块先按文本显示）；纪要总结与 AI 聊天气泡共用同一渲染器；XSS 过滤（AI 输出不信任，仅白名单标签）。
  • @纪要：消息 payload 带 memoId；模型经工具读 summary+sentences 文本（不灌音频）。
  • 重放与 seek：增量落盘音频文件，audio.currentTime = startMs/1000 句级跳转；播放跨句按时间找当前句高亮。
  • TTS 朗读：seed-tts-2.0 unidirectional/stream（整段流式合成）；音频边播边落盘可回听。
  • 崩溃恢复：句子粒度持久化 + 音频追加写 + 恢复 chip（v2 约定不变）；mock 伪造 utterances（含毫秒时间戳）供 e2e。

七、边界处理（v4 增量）

边界处理
3 分钟窗口与手动完成开：每满 3:00 自动结算一段（录音继续）；关：仅手动「完成」。结算前 12s 提示行倒计时；「完成」不足 3 分钟也立即结算。
段间衔接自动结算不打断 WS：句子序列号连续，段边界=结算时刻的句序；时间戳全程单调，重放无缝。
Markdown 流式渲染闪烁按块增量：完成块缓存静态 HTML，只重渲末尾未完块；未闭合代码块按普通文本显示，闭合后升格。AI 输出白名单过滤防 XSS。
总结引用的句子被改/删refs 指向句序不随文本变化；删除句后角标灰置不可点。
音频与句子时间错位start_time 服务端按音频时长给出，落库即绑定；漏段时 seek 跳最近可用位置并提示。
长纪要性能句子 item 虚拟化（复用 VirtualTimeline 经验）；block 视口附近渲染。
标题生成失败/超时兜底「语音 + 发起时间」，长按标题可手动改名。
reduced-motion闪烁降级为常亮 2s；声纹/波形动画停用。
