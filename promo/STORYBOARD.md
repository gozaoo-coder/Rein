# Rein 宣传片 · 分镜脚本

**规格**：1920×1080 · **60fps** · 60s · 30 个爆点，**每 2.0s 一个**。
节奏统一为「进入 0.5s → 停留 1.0s → 退出 0.5s」，爆点之间不许硬切（用同族缓动接力）。
配乐另有一条 120 BPM 的音轨（见 §3），一小节正好 2.0s —— 每个爆点天然落在强拍上。

## 0. 工程约定（写场景前必读）

```js
import { shell, pose, rise, sweep, breathe } from './_kit.js'

export function createScene() {
  const el = shell({
    n: 4,                                   // 序号（两位）
    label: '工具调用',                        // 底栏元信息
    eyebrow: 'TOOL CALLS · 工具调用',          // 眉标（缺省用 label）
    title: '它不只回答，还会动手',              // 场景标题：一行陈述句
    zone: 'k-split',                        // 内容区版式类（见下）
    inner: `…只写内容区里的东西…`,
  })
  const head = el.querySelector('.k-head')
  const rule = el.querySelector('.k-rule')
  return {
    id: '04-tools', label: '工具调用', at: 8, dur: 2, el,
    seek: (t) => { pose([head, rule], t); /* … */ },
  }
}
```

**版面骨架由 `shell()` 统一生成，场景不许自己摆标题。**
头带几何写在 `brand.css` 的 `--promo-*` 令牌里（版心左右 160px、眉标 y=104、通栏线 y=300、
内容区 336→984），全片同一个 y —— 连续性靠这套固定框，不靠相邻内容相似。
00 开场 / 29 收尾两枚书立不用头带。

**内容区版式（一屏一个焦点，非对称）**：

- `k-split` 左主角 2fr + 右副栏 1fr
- `k-split-r` 左副栏 1fr + 右主角 2fr
- `k-ladder` 左一列档位行（选中项放大上浮）+ 右侧单块大面板
- `k-stack` / `k-center` 竖直居中 / 整体居中

其余铁律：

- **确定性**：不许出现 CSS transition / animation（`brand.css` 全局关掉）。动效一律在 `seek(t)`
  里用纯函数算、写内联样式；文字与数字用 `lib/anim.js` 的 `seg()` / `counter()` 自己算。
- **元素引用只用 `el.querySelector`**，绝不用全局选择器（30 个场景同时在 DOM 里）。
- **视频尺度**：正文 21–26px，场景标题 56px（由 `shell()` 给），主数值用 `--fs-display-*`；
  任何**要读**的字 ≥ 14px。元素不得越出版心（160→1760）或所在卡片的圆角。
- **色彩配额**：数值与正文一律中性色（`--text-1/2/3`）；色相只出现在
  「图标 / 色点 / 进度条与图表 / 类型字章」上。每拍最多一个 accent 时刻。
- **停留段必须有动**：0.5–1.5s 的停留段里至少挂一处可见的动（扫光 / 呼吸 / 数值微动 / 光点流动）。
  任何 ≥0.6s 完全静止的段落会被审核判不通过。`sweep()` / `pulse()` / `breathe()` 是为它准备的。
- **离散状态也要走插值**：换行、切档这类「切换」不要硬切 —— 用一个 0.1–0.2s 的交叉淡化，
  或直接把参数（模糊、位置、高亮）写成 t 的连续函数。60fps 下这一步的差别看得见。
- **数字要自洽**：同一屏上的加减必须配平（如 2000 + 412 = 2412、5000 − 3224 = 1776）。
- 素材：`/shots/desktop-home.png`、`/shots/mobile-home.png`、`/shots/mobile-ledger.png`、
  `/shots/desktop-ledger.png`、`/shots/desktop-nutrition.png`、`/shots/workbench-home.png`、
  `/shots/muscle-front.png`。截图放进 `.win` / `.phone` 外壳，外壳外面**必须**套一层光的渐变（`.sheen`）才像玻璃。

## 2. 判定「完成」的标准

- `node render/shots.mjs` 抽出的 30 张静帧，每张单独看都是**一张成立的海报**：
  有明确焦点、有层次、没有空荡或拥挤。
- 任意相邻两帧之间**成对看不出硬切**（转场是同族缓动的接力，不是场景切换）。
- 每个爆点在停留段仍有可见的动（呼吸 / 微移 / 数值微动）。
- 逐张按检查表过：头带在且全片同一个 y；一屏只有一个焦点；无非对称；要读的字 ≥14px；
  没有彩色数值；没有空骨架；没有元素越出版心或卡片圆角；数字自洽；暗场进出无硬切。

## 3. 音轨（卡点配乐 + 音效）

`node render/music.mjs` 出一条 **60.00s / 120 BPM / 4/4** 的音轨（`out/rein-promo.wav`），
同时导出 `out/rein-promo.mid`（5 轨，可进 DAW 换音色）。

**为什么是 120 BPM**：一小节 = 2.0s = 一个爆点。于是第 k 个爆点永远落在第 k 小节的强拍上，
每个场景切点天然被一记软重音 + 和弦落点砸中 —— 卡点不需要逐拍对表。
音效（whoosh / tick / chime）也按同一个 2s 网格排。合成是**确定性**的（固定种子），
同一份代码渲两遍得到逐位相同的 wav。
