## 一、定位与形态

| | 抢课（Python） | Rein（Rust） |
|---|---|---|
| 形态 | CLI + `.bat` 一键启动 | Tauri 桌面 App（常驻后台线程 + 前端面板） |
| 状态 | 进程内存 + JSON 缓存 | **SQLite 落库**（任务/计划/设置），重启对账续跑 |
| 登录 | Playwright 操控浏览器（CDP），验证码人工 | 纯 HTTP（`ureq` + CookieJar + RSA），验证码人工 |
| 发射 | 4~8 连接并发，爬坡 2→20 次/秒 | **单线程 + 全局节流闸门**（默认 700ms，可调到 10ms） |
| 语法糖 | 名单文件（优先级 + 多选一） | 界面里写「计划」（一句查询 → 自动解析成志愿组） |

两边**不是竞品**：抢课是「一把梭的脚本」，Rein 是「常驻的抢课管家」。Rein 在状态持久化、错误分级、崩溃续跑上更强；抢课在**时钟精度、拉取/匹配的兜底层数、以及"被拒之后怎么换人"**上更成熟。

## 二、逐维度对比

| 维度 | 抢课 | Rein（本轮改造前） | 结论 |
|---|---|---|---|
| 时钟校准 | 多采样**区间交集**，实测 ±0.084s | 单次采样，整秒截断 ⇒ **系统性偏小 0~1s** | **抢课更优** → 已移植 |
| 占位预检 | 读 `messages[lessonId].textZh ≠ ATTEND` 即判死，不发正式请求 | 只看 `success`，**判死也继续发正式请求** | **抢课更优** → 已移植 |
| 受理单归属 | 单域，无此问题 | 双域时**镜像受理号被拿去问主域** | Rein 独有 bug → 已修 |
| 错误分级 | 简版（success/failed/resend/pending/timeout） | **9 类 Verdict + 分级耐心**（限流/5xx 不退避、参数错误交 AI） | Rein 更优 |
| 名额信息 | 用 `std-count` 批量查已选人数 | 直接读 `query-lesson.stdCount` —— **实测该部署根本不返回** | **抢课更优** → 待移植 |
| 匹配 | 打分权重 + **放宽阶梯 S0→S4**（严格→仅代码→仅课名→子串） | AND 分词 + 子序列匹配，**无放宽** | 各有取舍，抢课的放宽链更耐脏数据 |
| 被拒后 | **1 秒冷却 + 就地把候选换人**，20 次/秒连打 | 冷却后按 `full_retry_ms`（默认 **5 秒**）重试；组内换人靠手调 `cede_after_ms`（默认死守） | **抢课更优** → 已移植一半（窗口内加速） |
| 爬坡 | 开窗前 5 秒从 2/s 爬到 20/s | 无爬坡（匀速节流） | 抢课更优，但与 Rein「单线程可控」的取舍冲突，**暂不移植** |
| 双域 | 无 | **探测后两个域都发**（各自受理号、各自轮询） | Rein 更优 |
| 崩溃续跑 | 无 | `reconcile_on_start` + 先核对受理单再重投 | Rein 更优 |
| 自检 | `--preflight` 一键体检（名单/登录/令牌/时钟/轮次） | 无 | **抢课更优** → 待移植 |
| 课程缓存落盘 | `--dump-lessons` → JSON，抢课时优先读 | 仅内存 60 秒缓存 | 抢课更优 → 待移植 |

## 三、本轮对 Rein 的改造（全部已落地并有测试）

| # | 改动 | 证据 |
|---|---|---|
| 1 | **assoc 字段发数字**：教务用 Jackson 强类型接 `studentAssoc`/`courseSelectTurnAssoc`/`lessonAssoc`，此前我们发字符串 ⇒ **每一次提交都是 500** | 真机原文：`JSON parse error: Can not construct instance of …CourseSelectTurnAssoc: no String-argument constructor/factory method to deserialize from String value ('1921')`；修后占位 200 |
| 2 | **占位逐条判词**：`success:true` 只说明单子处理完了，`result.{lessonId}.textZh` 才是判词（`ATTEND` 才算过） | 真机回执 `{"success":true,"result":{"319505":{"textZh":"相同教学班只能选一次"}}}`；修后「占位被拒…提交 0 次」 |
| 3 | **时钟区间交集**：5 次采样取交集，误差收到往返时延量级 | 真机：旧口径 −361ms（系统性偏小）→ 交集 −210ms **±216ms**；另一次 ±88ms |
| 4 | **窗口内满员改为按节流节奏重投**（默认 700ms，而非 5 秒） | 单测 + 真机（满员课 5 秒取样等于每 5 秒才看一眼名额池） |
| 5 | **受理单归属**：新增 `request_domain` 列（迁移 0032）；镜像域的受理号只问镜像域；`verify_picked` 两个域都查 | 单测钉住 `pick_receipt`/`record_receipt`；双域真机无样本（本域没有第二个 EAMS5） |
| 6 | **占位单问对端点**：此前判据写反 ⇒ 拿占位号去问 `add-drop-response`，空转到上限才重投（默认白等 30 秒） | 单测钉住 `polls_predicate`；真机已走通 占位 → 转正式 |
| 7 | **解析失败归我们自己**：`JSON parse error`/`HttpMessageNotReadable` 判 `BadRequest`（停下交 AI），不再当「教务崩了继续打」 | 单测用真机原文 |
| 8 | **硬条件判终态**：`不符合选课条件组要求`、`相同教学班只能选一次` → `Fatal` | 真机原文；此前会白烧 8 次出手 |
| 9 | **错误正文带上**：`选课接口失败：HTTP 500` → 附响应体（200 字） | 正是这一步让 500 的真因（Jackson）当场定位 |
| 10 | `LessonQuery.can_select`：服务端资格过滤（引擎**不用**它，测试/预览用） | 真机：448 个班里本学生只有 12 个可选 |
| 11 | 时钟采样**只在没有任务等着出手时**做（有任务时读缓存） | 免得开窗那半秒被采样占用 |
| 12 | 浏览器 mock 同步为「占位 → 受理 → **正式确认**」两段式 | `e2e-auto-grab.mjs` 29/29 通过（"已尝试 N 次" 从此是真提交次数） |

**测试状态**：Rust 单测 330 通过 / 0 失败；浏览器 e2e 118/118 通过（auto-grab 29、squads 19、plan 30、emergency 19、course-select 21）。
**真机联调**：登录 → 令牌 → 时钟 → 学生 → 批次（1921，窗口 09-21 10:00 ~ 09-30 23:00）→ 448 个教学班 → 匹配 → 志愿组 → 开火时刻，**全部通过**；写链路走到「占位受理 + 正式请求拿到真实业务回复」。
**选课记录**：联调前后均为 15 门，**一门未增、一门未减**（原有必修全部完好）。

## 四、真机联调暴露的、抢课项目里写错的结论

| 抢课的说法 | 实测/源码核对结果 |
|---|---|
| `--auto-resend` 带 `needAttend=true` 重发，对应前端「免听」按钮 | **反了**。前端 i18n：`resend:"免听"` → `resendOpeation(false)`、`noResend:"不免听"` → `resendOpeation(true)`，函数体是 `e.needAttend = t`。**免听 = `needAttend:false`**，`true` 是「不免听」 |
| 占位/正式提交的请求体「据源码逆向，待开抢时确认」 | 字段名对，但 **assoc 类型必须是数字**（字符串直接 500）—— 这条两边都没验证过 |
| 用 `query-lesson` 的 `stdCount` 判断满没满 | 该部署**不返回 `stdCount`**（448/448 缺失），只能走 `std-count` 批量接口 |
| 占位可以反复发、代价只是多一轮往返 | 占位回执**逐条判词**；判死的课再发正式请求是纯浪费 |

|---|---|---|---|
| **P1** | **座位数**（`std-count` 批量查已选人数） | `CourseSelectClient::std_count`（200 一批）+ 引擎与预览共用的 `fill_seats`（30 秒缓存）+ `matcher::rerank` 补完重排 | **✅ 已移植**，真机验证「余 3 / 2 / 5」 |
| **P2** | **匹配放宽阶梯** | `matcher::match_lessons_relaxed`：严格 → 丢死词（DropNoise）→ 丢笼统的时间地点词（DropCommon） | **✅ 已移植**，真机验证 |
| **P3** | **被拒后就地换人** | `REJECT_COOLDOWN_MS`（1 秒，且**必须长于节流间隔**）+ `group_lead` 只从「已到点」的候选里挑当前志愿 | **✅ 已移植** |
| **P4** | **起飞前自检** | `campus_grab_preflight` 命令 + 面板上的「起飞前自检」按钮（逐项 GO·NO-GO + 证据） | **✅ 已移植** |
| **P5** | **课程缓存落盘** | `LessonsDump`（原子写、按批次校验）；**只在拉不到名单时兜底**，并把「这是旧名单」写到界面 | **✅ 已移植** |
| **P6** | 停止条件补齐 | 批次从 `open-turns` 消失即收手（要**上架过**才判撤下、手上有受理单的不收） | **✅ 已移植** |
| **P7** | 爬坡发射 | 与 Rein「单线程 + 全局闸门」冲突；本轮以「窗口内满速守名额 + 被拒轮换」替代 | 不移植（有意） |
| **P8** | 报告链路 | 任务行已有 `attempts`/`lastMessage`，新增「X 秒后重试」把冷却说清楚 | ✅ 够用 |

### P2 的两条红线（都是测试逼出来的）

放宽这件事听起来无害（「反正零结果」），但它能**替用户换掉一门课**，所以定了四条边界：

1. 严格档**有命中就绝不放宽**；
2. **像人名的词永不丢**（「张伟」查不到张伟的班 = 没找到，不是「随便哪位老师都行」）；
3. **课程代码形状的词永不丢**（写错一位就是零命中，不许退回按课名匹配 —— 与既有测试同一条分寸）；
4. **丢完之后必须还认得是哪门课**：剩下的词至少要有一个落在课程名/代码上。
   这条是**端到端测试逼出来的**：`高数 无此条件` 那种查询该放宽，而
   `量子力学 张伟`（名单里没有量子力学）如果丢掉课程名，就会去抢**张伟的别的课** ——
   e2e 当时真的匹配出了一门高等数学，规则就是在那时候补上的。

## 六、前端（本轮）

| 改动 | 说明 |
