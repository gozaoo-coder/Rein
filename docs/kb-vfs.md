# Rein 虚拟文件系统规范（kb-vfs）

> 知识库把全部应用数据与用户文件统一编目成一片「文件树」。本文是这份规范的权威定义；
> 同一内容会作为只读系统文件 `规范/知识库规范.md` 播种进知识库，供 AI 随时查阅自身约定。
> 目标态与需求映射见 `docs/ai-workspace.md`（实现落地后并入本文档）。

## 1. 两个世界：派生文档 与 真实文件

| | 派生文档（只读） | 真实文件（可写） |
|---|---|---|
| 存储 | 由 11 张源表派生，`kb_docs.body` 是缓存 | `kb_files` 表，内容即真源 |
| 身份 | `source_type` + `source_id` | `kb_files.path`（唯一） |
| 编辑 | 改源数据（触发器自动重索引） | 直接编辑 / 改名 / 移动 / 删除 |
| `editable` | 0 | 1（`system=1` 的系统文件为 0） |

**派生文档永远只读。** 它们是应用数据的影子；要改内容就去改对应功能里的数据，
索引线程会在数秒内重放。任何「直接改 kb_docs」的尝试都会在下一次重放被覆盖。

**本体与文本分离。** 音频 / 视频 / 图片 / 二进制文件的字节**绝不进索引正文**，只以引用登记在
模态层（§7）；能派生出文本的（转录 / 描述）以文本模态参与检索。

## 2. 路径命名空间

| 前缀 | 内容 | 来源 | 可写 |
|---|---|---|---|
| `系统提示词/*.md` | 系统提示词（角色与语气、工作区约定） | `kb_files(system=1)` | ✗（随版本更新，§9 全量注入） |
| `规范/知识库规范.md` | 本文档 | `kb_files(system=1)` | ✗ |
| `用户记忆/角色设定.md`、`用户记忆/全局规范.md` | 用户长期设定与规则 | `kb_files` | **✓**（每轮全量注入，§9） |
| `未分类数据/{日期}/…` | 收件箱：新内容未归类前的落点 | `kb_files` | **✓**（AI 归类后移出，§8） |
| `笔记/{名称}.md` | 用户笔记 | `kb_files` | **✓** |
| `文档/{文件名}.md` | 上传文档的**全文**归档（发送时自动写入；prompt 只带截断版，AI 经 L2 分页读全文） | `kb_files` | **✓** |
| `语音/{日期}/{标题}-{id}.md` | 语音纪要（文本模态） | `voice_memos` | ✗ |
| `日程/{日期}/{标题}-{id}.md` | 待办（含子任务、附件目录） | `todos` | ✗ |
| `附件/日程/{todoId}/{序号}-{文件名}` | 待办附件编目 | `todos.attachments` | ✗ |
| `运动/{日期}/{名称}-{id}.md` | 训练记录（逐组明细聚合） | `workouts` + `workout_sets` | ✗ |
| `课程/{名称}-{id}.md` | 训练课程（动作与要领） | `workout_plans` | ✗ |
| `饮食/{日期}/{餐次}-{食物}-{id}.md` | 饮食记录 | `meal_logs` | ✗ |
| `体测/{日期}-{id}.md` | 体重身高 | `body_metrics` | ✗ |
| `食物/{名称}-{id}.md` | 自建食物 | `foods(is_custom=1)` | ✗ |
| `方案/{目标}-{档位}-{id}.md` | 健康方案（含调整历史） | `programs` | ✗ |
| `菜单/{日期}-{方案id}.md` | 方案当日菜单 | `program_meals` | ✗ |
| `对话/{标题}-{chatId}.md` | 会话（含全文转录，分页阅读） | `ai_chats` | ✗ |
| `对话/{chatId}/{seq}-{角色}.md` | 单条消息 | `ai_chat_messages` | ✗ |
| `附件/对话/{messageId}/{序号}-{文件名}` | 对话里的图片/文档 | 消息附件 | ✗ |
| `记忆/{类型}/{主题}-{id}.md` | 长期记忆（有分类时为 `记忆/{类型}/{分类}/{主题}-{id}.md`） | `kb_memories` | **✓**（经记忆 API） |
| `视频/…`、`语音/…`（用户子区） | 用户自己的音频 / 视频本体与整理产物 | `kb_files` | **✓** |
| 领域目录下的用户子目录（如 `运动/知识/…`） | 用户按领域整理的文件 | `kb_files` | **✓** |

命名规则：路径段做**净化**——`/ \ : * ? " < > |` 与控制字符替换为 `-`，超长截断；派生文档一律带 `-id` 后缀保证唯一。

**保留区（用户文件自动让位）**：`附件/` 全树、任何 `YYYY-MM-DD` 日期目录、以 `-数字` 结尾的文件名
都是派生文档的形态。用户文件写进这些形态时由 `governance::free_path` 自动改道，**绝不覆盖派生文档**：

- 领域目录（日程/运动/课程/…）下的文件名带 `-数字` 后缀 → 加 `-v2`（`课程/腿部-42.md` → `课程/腿部-42-v2.md`）；
  知识区（笔记/文档/未分类数据/语音/视频/用户记忆）不受这条限制——`安排表9-10.md` 是正常文件名；
- 目录段是日期目录 → 整段让位加 `-用户`（`运动/2026-09-10/腿部-42.md` → `运动/2026-09-10-用户/腿部-42-v2.md`）；
- `附件/` 是编目树，用户内容改投收件箱（`附件/日程/t1/照片.jpg` → `未分类数据/照片.jpg`）。

## 3. 分层与分页（L0 / L1 / L2）

- **L0**（`summary`）：正文首句，≤120 字。`search_knowledge` 返回的就是这一层。
- **L1**（`level:"l1"`）：摘要 + 首块。判断相关性用。
- **L2**（`level:"l2"`）：分块正文，支持 `offset`/`limit` 分页（默认取 8 块）；
  响应带 `totalChunks` / `offset` / `hasMore`，AI 逐页读，不一次性倾倒。

**阅读以真源为准（note 源）**：笔记与上传文档归档的真源在 `kb_files`，`kb_docs.body`
只是带截断上限的检索缓存。`kb_read` 对 note 源直读真源原文并按同一分块参数即时切块，
所以全文超过缓存上限（8000 字）时，L2 分页依然能读到结尾——检索缓存只影响召回，不影响阅读完整性。
上传文档在发送时全文归档进 `文档/`（prompt 只带 6000 字截断版并注明归档路径），
用户追问「继续看后面」时 AI 应 glob `文档/**` 定位后 L2 分页读全文。

用户侧的浏览入口是「AI 页 › 文件」（`/ai/files`，文件管理器）与「知识库 › 文件库」（`/ai/knowledge/files`，同一页面）：
目录式下钻浏览全部命名空间，阅读器同样直读真源 / 渐进加载分块，保证看到的是完整内容。

## 4. 检索方式

| 方式 | 工具 | 说明 |
|---|---|---|
| 语义/关键词 | `search_knowledge` | FTS5 trigram → LIKE → 二字窗口模糊，加向量召回，RRF 融合 |
| 按路径 | `glob_knowledge` | `*` 不跨目录、`**` 跨目录、`?` 单字符；如 `笔记/*.md`、`对话/**/*.md` |
| 逐页细读 | `read_knowledge` | 按 id + level + offset/limit |
| 取本体模态 | `read_modal` | 音频/视频/图片按需取；不可用则降级为文本（§7） |

**索引范围**：只有 text 模态、以及可派生出 text 的模态（转录 / 字幕 / OCR / 描述）进 FTS 与向量；
本体字节只登记元信息（mime、字节数、时长），永远不进索引正文。

## 5. 附件编目原则

附件的**二进制内容绝不进索引正文**。编目记录的是：类型、文件名、体积、所属父文档；
`text` 类附件的正文才进入索引。要看图片/音频本体，用 `read_modal` 取（或回到源数据：
待办详情 / 对话消息）。

## 6. 记忆的编辑与生命周期

记忆是知识库里唯一「AI 与用户都能改」的派生文档：
- AI：`edit_memory`（改内容/主题/类型/分类）、`forget`（删除）——都走 `kb_memory_apply`，留 `kb_memory_diffs` 审计；
- 用户：知识库页的记忆区直接改/归档/删。
改动会自动重新入索引，并在下一轮对话的【用户认知】段生效（缓存 ≤60 秒）。

**生命周期**（记忆会淡忘，而不是只增不减的日志）：

| 机制 | 说明 |
|---|---|
| 显著性 | `置信度 × 0.5^(闲置天数/14) × (1 + ln(1+注入次数)/4)`，读时计算不落库；认知块按它降序取前 24 条 / 1200 字符 |
| 使用强化 | 每次注入 `active_count + 1` 并刷新 `last_used_at`，衰减重新计时 |
| 自动归档 | 启动时与每 6 小时一次（后台线程搭车，无模型调用）：从未被注入且闲置 >30 天，或显著性 <0.15 且闲置 >45 天 → 归档（`archived_reason='decay'`） |
| 归档语义 | **软删除**：退出注入与检索两条链路（派生文档即刻摘除），仍可在知识库页「显示归档」恢复；再次被提及（update / 重复 add）自动复活 |
| 分类层级 | `category` 为 1~2 层路径（如 `健康/训练`），由抽取与整理任务给出，随路径落到 `记忆/{类型}/{分类}/…` |
| LLM 整理（“做梦”） | 每天最多一次（会话结束或启动时检查，可在设置关掉）：合并跨会话重复、统一分类、校准置信度、归档噪声、清理归档区里确认无价值的条目 |
| 信噪比 | 知识库页展示：注入覆盖率（实际注入/活跃）、低信号占比（显著性 <0.15 的活跃条数占比）、归档数、最近维护/整理时间 |

## 7. 模态层（kb_assets）

一条数据可以有多种模态，它们是**同一个节点**的不同表示，不是多个文件：

```
语音/2026-09-19/晨会-m1.md        text   转录与要点（检索用）
（本体）voice/a.wav                audio  音频本体（kb_assets 引用）
视频/会议录像.mp4                  video  视频本体
视频/会议录像.md                   text   描述 / 字幕（检索用）
```

- 本体三来源：上传进工作区的 `kb_assets`（storage=fs，落在应用数据目录）、语音纪要的 wav
  （`voice_memos.audio_path`）、附件里的 data URL（待办 / 对话）。
- **降级链**：请求 audio/video/image 时——有本体就返回本体（前端可播放；字节不走 base64 进模型上下文），
  没有就**降级为文本**并给原因（`degraded` + `degradeReason`），永不报错、不空转。
- **转写状态**：`none → pending → done | failed`。未转写的音频/视频取文本会得到降级说明。
- 超大的本体不内联（`tooLarge`），元信息照给，由界面导出。

## 8. 目录治理（AI 主动分类）

**四区**：

| 区 | 目录 | 可写 | AI 可整理 |
|---|---|---|---|
| 系统区 | `系统提示词/`、`规范/` | ✗ | ✗ |
| 记忆区 | `用户记忆/` | ✓（固定路径） | 仅改内容，不移动 / 改名 |
| 投影区 | `日程/ 运动/ 饮食/ …` 里的派生文档 | ✗ | ✗（要改就改源数据） |
| 知识区 | `笔记/ 文档/ 未分类数据/ 语音/ 视频/` + 领域目录下的用户子目录 | ✓ | ✓（建目录 / 移动 / 打标） |

**分类规则**（`classify_move` / `make_folder` / `pin_file`）：

1. 新内容常落 `未分类数据/`——AI 有整理职责：看内容归到语义合适的目录，`reason` 写清依据；
2. 结构约束：深度 ≤ 4 层、同级 ≤ 50 条、一次批量 ≤ 200；
3. **防抖**：同一文件 24 小时内不会被自动移动第二次；按内容归类，不按时间瞎挪；
4. **用户优先**：用户手动放置或被 `pin` 钉住的文件，AI 不得移动；
5. 一切移动写 `kb_fs_moves` 审计（谁 / 何时 / 从哪到哪 / 为什么），可按 `batchId` 整批撤销。

## 9. 全量注入区（每轮对话都进提示词）

| 注入项 | 来源 | 时机 |
|---|---|---|
| 系统提示词 | 代码静态段（工具与输出协议）+ `系统提示词/*.md` | 每轮 |
| 用户记忆 | `用户记忆/*.md` 全文 | 每轮 |
| 认知块（长期记忆） | `kb_cognition()` | 每轮（TTL 60 秒） |
| 其他所有内容 | 检索 / 工具按需 | **不注入** |

- 预算 12,000 字符；超限按「系统提示词 > 角色设定 > 全局规范 > 其他」截断，并在提示里注明。
- 只有 HTML 注释的模板文件（用户记忆初始态）不占预算，但在文件管理器里可见、可编辑。
- 系统提示词与用户记忆都是文件：想看 AI 现在被喂了什么，直接打开这两个目录即可。
