# Rein 虚拟文件系统规范（kb-vfs）

> 知识库把全部应用数据与用户文件统一编目成一片「文件树」。本文是这份规范的权威定义；
> 同一内容会作为只读系统文件 `规范/知识库规范.md` 播种进知识库，供 AI 随时查阅自身约定。

## 1. 两个世界：派生文档 与 真实文件

| | 派生文档（只读） | 真实文件（可写） |
|---|---|---|
| 存储 | 由 11 张源表派生，`kb_docs.body` 是缓存 | `kb_files` 表，内容即真源 |
| 身份 | `source_type` + `source_id` | `kb_files.path`（唯一） |
| 编辑 | 改源数据（触发器自动重索引） | 直接编辑 / 改名 / 删除 |
| `editable` | 0 | 1（`system=1` 的规范文件为 0） |

**派生文档永远只读。** 它们是应用数据的影子；要改内容就去改对应功能里的数据，
索引线程会在数秒内重放。任何「直接改 kb_docs」的尝试都会在下一次重放被覆盖。

## 2. 路径命名空间

| 前缀 | 内容 | 来源 | 可写 |
|---|---|---|---|
| `日程/{日期}/{标题}-{id}.md` | 待办（含子任务、附件目录） | `todos` | ✗ |
| `附件/日程/{todoId}/{序号}-{文件名}` | 待办附件编目 | `todos.attachments` | ✗ |
| `运动/{日期}/{名称}-{id}.md` | 训练记录（逐组明细聚合） | `workouts` + `workout_sets` | ✗ |
| `课程/{名称}-{id}.md` | 训练课程（动作与要领） | `workout_plans` | ✗ |
| `饮食/{日期}/{餐次}-{食物}-{id}.md` | 饮食记录 | `meal_logs` | ✗ |
| `体测/{日期}-{id}.md` | 体重身高 | `body_metrics` | ✗ |
| `食物/{名称}-{id}.md` | 自建食物 | `foods(is_custom=1)` | ✗ |
| `方案/{目标}-{档位}-{id}.md` | 健康方案（含调整历史） | `programs` | ✗ |
| `菜单/{日期}-{方案id}.md` | 方案当日菜单 | `program_meals` | ✗ |
| `纪要/{标题}-{id}.md` | 语音纪要 | `voice_memos` | ✗ |
| `对话/{标题}-{chatId}.md` | 会话（含全文转录，分页阅读） | `ai_chats` | ✗ |
| `对话/{chatId}/{seq}-{角色}.md` | 单条消息 | `ai_chat_messages` | ✗ |
| `附件/对话/{messageId}/{序号}-{文件名}` | 对话里的图片/文档 | 消息附件 | ✗ |
| `文档/{文件名}.md` | 上传文档的**全文**归档（发送时自动写入；prompt 只带截断版，AI 经 L2 分页读全文） | `kb_files` | **✓** |
| `记忆/{类型}/{主题}-{id}.md` | 长期记忆 | `kb_memories` | **✓**（经记忆 API） |
| `笔记/{名称}.md` | 用户笔记 | `kb_files` | **✓** |
| `规范/知识库规范.md` | 本文档 | `kb_files(system=1)` | ✗（系统文件） |

命名规则：路径段做**净化**——`/ \ : * ? " < > |` 与控制字符替换为 `-`，超长截断；派生文档一律带 `-id` 后缀保证唯一。

## 3. 分层与分页（L0 / L1 / L2）

- **L0**（`summary`）：正文首句，≤120 字。`search_knowledge` 返回的就是这一层。
- **L1**（`level:"l1"`）：摘要 + 首块。判断相关性用。
- **L2**（`level:"l2"`）：分块正文，支持 `offset`/`limit` 分页（默认取 8 块）；
  响应带 `totalChunks` / `offset` / `hasMore`，AI 逐页读，不一次性倾倒。

**阅读以真源为准（note 源）**：笔记与上传文档归档的真源在 `kb_files`，`kb_docs.body`
只是带截断上限的检索缓存。`kb_read` 对 note 源直读真源原文并按同一分块参数即时切块，
所以全文超过缓存上限（8000 字）时，L2 分页依然能读到结尾——检索缓存只影响召回，不影响阅读完整性。
上传文档在发送时全文归档进 `文档/`（prompt 只带 6000 字截断版并注明归档路径），
用户追问「继续看后面」时 AI 应 glob `文档/**` 定位后 L2 分页读全文。

用户侧的浏览入口是「知识库 › 文件库」（`/ai/knowledge/files`）：
目录式下钻浏览全部命名空间，阅读器同样直读真源 / 渐进加载分块，保证看到的是完整内容。

## 4. 检索方式

| 方式 | 工具 | 说明 |
|---|---|---|
| 语义/关键词 | `search_knowledge` | FTS5 trigram → LIKE → 二字窗口模糊，加向量召回，RRF 融合 |
| 按路径 | `glob_knowledge` | `*` 不跨目录、`**` 跨目录、`?` 单字符；如 `笔记/*.md`、`对话/**/*.md` |
| 逐页细读 | `read_knowledge` | 按 id + level + offset/limit |

## 5. 附件编目原则

附件的**二进制内容绝不进索引正文**（图片/文件/音频在前端以 base64 data URL 内联存储，
一条可达数百 KB）。编目记录的是：类型、文件名、体积、所属父文档；`text` 类附件的正文才进入索引。
要看图片本体，用父文档 id 回到源数据（待办详情 / 对话消息）取。

## 6. 记忆的编辑

记忆是知识库里唯一「AI 与用户都能改」的派生文档：
- AI：`edit_memory`（改内容/主题/类型）、`forget`（删除）——都走 `kb_memory_apply`，留 `kb_memory_diffs` 审计；
- 用户：知识库页的记忆区直接改/删。
改动会自动重新入索引，并在下一轮对话的【用户认知】段生效（缓存 ≤60 秒）。
