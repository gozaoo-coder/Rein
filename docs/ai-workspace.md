## 1. 数据模型：一切数据皆文件

### 1.1 三律（不可违反）

1. **真源唯一**：每类数据有一张源表。工作区只做编目投影，不产生第二份真源；
2. **派生只读**：投影文档由源表派生，重放即覆盖。要改内容 → 改源数据或走对应命令，不许直接改 `kb_docs`；
3. **本体与文本分离**：二进制本体（音频/视频/图片/文件）**绝不进索引正文**，只登记引用与元信息（沿用现约束，有单测硬断言）。

### 1.2 来源清单

| 域 | source_type | 状态 |
| --- | --- | --- |
| 日程（含备注、子任务） | `todo` | 已有（备注在正文里，可检索） |
| 日程附件 | `todo_attachment` | 已有（仅编目）→ v2 升级为「本体 + 模态」 |
| 对话 / 消息 / 消息附件 | `chat` `chat_message` `chat_attachment` | 已有 |
| 语音纪要 | `voice_memo` | 已有（文本 + 音频本体经模态层可取） |
| 视频 / 通用文件 | `note`（多模态节点，`kb_files.kind='multimodal'`） | 已接入：`kb_media_write` 落本体 + 描述/转录文本模态；**不建独立 `video_memo` 源表**（没有原生录制入口时，它只会是一张空表） |
| 运动 / 课程 / 饮食 / 体测 / 食物 / 方案 / 菜单 | 各自 | 已有 |
| 记忆 / 笔记 / 上传文档 | `memory` `note` | 已有 |
| 记账 / 画像 | `ledger` `profile` | P2 评估（表格化数据，编目价值待验证） |

新增一类数据 = 固定五步（见 §7），**漏一步视为不可合并**。

### 1.3 索引范围（要求 3 后半）

- 进 FTS + 向量的：**text 模态**，以及**可派生出 text 的模态**（转写 / 字幕 / OCR / 视觉描述）。
- 不进索引的：音频/视频/图片/二进制的本体字节，只存元信息（mime、字节数、时长、宽高）。
- 派生文本的来源在命中结果里标注：`modal:"derived"` + `derivedFrom:"audio" | "video" | "image"`，让 AI 知道「这句话来自转写，不是用户原话」。

## 2. 模态层：一个文件，多种模态（要求 2）

### 2.1 概念

一个**逻辑文件**（树上一个节点）= 一组**模态表示**。同一件事的文本、音频、视频、截图不是四个文件，而是一个节点的四种模态：

```
纪要/2026-09-19/晨会-42/          ← 逻辑文件（多模态目录）
├── 纪要.md        text   （转录 + 要点；可被检索/嵌入）
├── audio.wav      audio  （本体；duration 32:10）
├── video.mp4      video  （本体；可选）
└── 白板-12m.png   image  （关键帧 / 截图）
```

数据模型（v2 新增，落库）：

- `kb_files` 扩展：`kind`（`text` | `multimodal`）、`pinned`、`classify_state`（`inbox` | `filed` | `manual`）；
- `kb_assets`（新）：`(id, file_id, modal, mime, storage, ref, bytes, duration_ms, width, height, transcript_state, derived_from, created_at)`；`storage` ∈ `inline`（小文本）/ `fs`（应用数据目录下的相对路径）。

### 2.2 模态与降级链

| 请求模态 | 可用时返回 | 不可用时降级 | 返回标注 |
| --- | --- | --- | --- |
| text | 文本（L0/L1/L2 分页照旧） | — | — |
| audio | 本体引用（mime / duration / 播放句柄） | 转写文本 | `degraded:"text"`，原因（`未转写` / `无音轨`） |
| video | 本体引用（mime / duration / 关键帧清单） | 音轨转写 → 文本 | 同上 |
| image | 本体引用 | 视觉描述 / OCR 文本 | 同上 |
| 其他 binary | 本体引用（导出 / 外部打开） | 文件名 + 类型 + 体积描述 | 同上 |

规则：**降级永远发生，不许失败**；任何读取结果都带 `modalities[]`（该节点实际可用的模态）与 `degraded` 说明——AI 必须能判断「拿到的是不是原件」。

### 2.3 访问与产出

- **读**：`read_knowledge` 增加 `modal` 参数。本体不走 base64 进上下文，而是返回**引用对象**（`assetId / path / mime / duration`），需要展示时由前端渲染。
- **产出**：AI 生成的多模态产物（纪要、朗读音频、录屏）走 `write_modal`：先落本体，再写文本模态，节点一并登记；**没有文本模态的产物必须补一段描述正文**，保证可检索。
- **输出协议**：`{"kind":"chat","text":"…","modals":[{assetId, modal, mime, duration}]}`，前端渲染音频条 / 视频播放器 / 图片查看器；不支持渲染的模态给「导出」入口。

### 2.4 转写状态机

`none → pending → done | failed`。`pending / failed` 时：检索只吃已有文本模态；对 audio/video 请求明确降级并给可操作提示（「转写尚未完成，可稍后重试」），**不报错、不空转**。

## 3. 目录治理：AI 主动分类（要求 3）

### 3.1 默认目录（目标态）

```
/系统提示词/          # 系统只读 · 代码播种 · 全量注入
/用户记忆/            # 可写 · 固定路径 · 全量注入
    角色设定.md
    全局规范.md
/规范/                # 系统只读（kb-vfs.md 播种，现有）
/日程/ /运动/ /饮食/ /体测/ /课程/ /食物/ /方案/ /菜单/ /对话/ /附件/ /记忆/   # 应用投影（派生只读）
/语音/                # 新增：语音本体 + 转写派生（原 纪要/ 并入）
/视频/                # 新增：视频本体 + 转写 / 字幕派生
/文档/                # 上传文档全文归档（现有，可写）
/笔记/                # 手写笔记（现有，可写）
/未分类数据/          # 收件箱（可写）：新内容先进这里，再由 AI 归类
```

### 3.2 四区与写权限

| 区 | 目录 | 可写 | AI 可整理 |
| --- | --- | --- | --- |
| 系统区 | `系统提示词/` `规范/` | ✗ | ✗ |
| 记忆区 | `用户记忆/` | ✓（固定路径） | 仅改内容，不移动 / 改名 |
| 投影区 | `日程/` `运动/` `饮食/` … `记忆/` | ✗（派生文档） | ✗（要改就改源数据） |
| 知识区 | `笔记/` `文档/` `语音/` `视频/` `未分类数据/` + 投影区下的用户子目录 | ✓ | ✓（建目录 / 移动 / 改名 / 打标） |

**保留区规则**：投影文档的路径段（`{日期}/`、`-{id}` 后缀）为保留命名；`kb_files` 写入与之冲突时自动加后缀，**绝不覆盖派生文档**。

### 3.3 分类引擎

- **触发**：① 新文件落 `未分类数据/` → 会话结束时批量归类；② 用户显式要求（「整理一下」）。
- **工具**：`classify_move`（移到目标目录）、`mkdir`、`pin`（钉住，AI 不再移动）、`tag`。
- **规则**（写进系统提示词与工具描述）：
  1. 只动知识区；投影区只读；
  2. 结构约束：深度 ≤ 4、同级条目 ≤ 50、命名走 `sanitize` 同规、单次批量 ≤ 200；
  3. **防抖**：同一文件 24h 内不再自动移动；按内容归类，不按时间瞎挪；
  4. **用户优先**：用户手动放置 / 钉住的，AI 不得覆盖；一切移动写 `kb_fs_moves` 审计（谁 / 何时 / 从哪到哪 / 为什么），可整批撤销；
  5. **结构调整**（重命名 / 合并目录）必须留审计且可撤销，一次会话最多一次。
- **脚手架**：不预建空目录；默认分类目标是既有的领域目录（运动 / 饮食 / 日程 / …），确实无处可放才新建目录。

### 3.4 全量注入区（要求 3 后半）

| 注入项 | 来源 | 时机 |
| --- | --- | --- |
| 系统提示词 | 代码静态段（工具协议 / 输出协议）+ `系统提示词/*.md`（按文件名排序拼接） | 每轮 |
| 用户记忆 | `用户记忆/*.md` 全文 | 每轮 |
| 认知块（长期记忆） | `kb_cognition()`（现有实现，TTL 60s） | 每轮 |
| 其他所有内容 | 检索 / 工具按需 | **不注入** |

- **预算**：注入区总长 ≤ 12,000 字符（建议值，可配置）。超限按优先级截断：系统提示词 > 角色设定 > 全局规范 > 其他，并在提示里注明「有内容被截断」——让 AI 主动去读，而不是装作没这回事。
- **实现衔接**：`buildChatSystemPrompt()` 的静态段改为「读 `系统提示词/` + 拼接」，读结果按 mtime 缓存；`用户记忆/` 缺失时静默跳过（沿用 `cognitionForPrompt` 的容错原则：注入失败绝不阻塞对话）。

## 4. 检索

- 范围：§1.3 定义的文本模态与派生文本；三档模式（keyword / local / cloud）、RRF 融合、L0/L1/L2 分页全部沿用。
- 索引来源开关（`sources_enabled`）增加 `video_memo` 等新来源，默认开启。
- 命中结果区分「原文」与「转写」：转写标注 `derivedFrom`，避免 AI 把 ASR 文本当用户原话引用。

## 5. 文件管理器（要求 4）

### 5.1 入口

- AI 页 `PageHeader` 的 `#lead` 槽（**左上角**）新增文件按钮：`Folder` 图标、`.hdr-btn` 规格（38px 圆形、`--surface` 底、`--shadow-card`）、`aria-label="文件"`。
- 点击 → 文件管理器（建议路由 `/ai/files`，升级现 `FileLibraryPage.vue`；`/ai/knowledge/files` 保留为别名/重定向）。
- **自研、不调外部**：只经 `kb_*` 命令访问虚拟文件系统，不读物理路径、不唤起系统文件管理器。
- **聊天里的文件卡片（2026-10-08）**：AI 用 `present_file` 把一份产出挂到气泡下面（笔记 / 解压出来的文件 / 用户要找的东西）。
  点卡片 = 按路径深链进文件管理器（`?dir=&path=`，文件进阅读器；目录卡片直接进该目录），
  与空间总览的大文件榜同一条链路（都按路径而不是 id —— 卡片拿到的可能是 `kb_files.id`，
  而阅读器要 `kb_docs.id`）。卡片与文件管理器**共用图标与视图模型**（`FileIcon` + `toFileItem`），
  所以同一条文件在两处长一样。

### 5.2 功能面

- **浏览**：面包屑 + 目录下钻 + 命名空间（地标卡）+ 当前目录过滤 + 「在整个工作区找」；空目录也要可见。
- **视图**：列表（详细列：名称 / 类型 / 大小 / 修改时间）与网格（图标三档：小 / 中 / 大）两种；
  排序（名称自然序 / 修改时间 / 大小 / 类型，升降序、目录优先可关）、分组（不分组 / 类型 / 日期 / 大小）、
  显示隐藏文件、隐藏已知扩展名；偏好记在 `localStorage`（`rein.files.prefs.v1`）。
  宽屏列表上方有**可点的列头**（箭头标出方向，再点同一列翻转升降序），窄屏走工具条的排序菜单。
- **大目录不卡**：行级虚拟滚动（`src/files/virtualRows.ts`，前缀和 + 二分，分组标题行高度不同也算得准）；
  缩略图异步生成（`thumbs.ts`：`createImageBitmap` + canvas 缩放 + LRU 缓存 + 并发上限 2 + 失败缓存空值），
  不阻塞列表、不重复解码。
- **预览**：text（L2 分页「继续加载 / 一次读完」）、image / audio / video（本体播放）、binary（元信息 + 导出）。
  压缩包点开是**包内浏览**（`zip://` 层：按包内路径逐级走、可选择性解压），不是丢给系统解压工具。
- **文件信息**：路径、来源类型、模态清单、大小 / 时长、修改时间、分类状态、可写 / 只读 / 系统锁、钉住态。
- **选择**：单击 / Ctrl 切换 / Shift 范围 / 全选 / 反选；方向键、Home / End、PageUp / PageDown、
  Enter、空格预览、F2、Delete、Backspace 上一级、Esc、Ctrl+C/X/V/A；打字跳转。
  选择按**稳定 id** 保存，刷新 / 排序 / 过滤 / 换视图后不丢。
- **操作**：新建目录 / 导入文件 / 重命名（就地 F2，扩展名受保护、改动时警告）/ **批量重命名**（查找替换 +
  前后缀 + 编号，带实时预览与冲突校验）/ 移动（拖放或菜单，修饰键 Ctrl = 复制）/ 复制到目录 / 钉住 /
  删除（**默认进回收站**，可撤销）/ 回收站恢复 / 彻底删除 / 清空 / **导出到本地**（桌面落「下载/Rein」，
  浏览器触发下载）。
- **标签 / 评分 / 注释**：用户给文件加的话，存在 `kb_files`（`rating` / `tags` / `note`），
  **不进索引**——标签里的词进检索会把「训练」这类词变成到处都是的噪声词；可排序、可按标签筛选（多选 = 都要满足）。
- **列可配置**：内置名称 / 类型 / 大小 / 修改时间 / 评分 / 标签 / 来源，列菜单里增删（宽屏表格式生效）。
- **扩展点**（`src/files/registry.ts`）：列 / 上下文菜单 / 属性面板 / 预览偏好 / 图标五类 provider，
  内置能力（压缩包、存储）本身就是第一批注册者——云盘、Git 这类将来的 provider 走同一条路进来。
- **同名冲突策略**：粘贴 / 导入 / 拖入时若目标已有同名，问一次「替换 / 跳过 / 保留两者」，可记住本次会话的选择
  （更多菜单里随时改回「每次都问」）；保留两者按 `-v2` 让位，替换 = 先把挡路的送进回收站再写。
- **框选**：鼠标拖出方框多选（Ctrl 拖 = 叠加），触屏不启用（拖拽留给滚动）。
- **视图**：列表 / 网格 / **画廊**（只看图片视频的大图块）/ **分栏**（Finder 式栏链，点目录往右加一栏）四种，
  外加可开关的**目录树**侧栏（只列目录、按需展开、当前路径自动展开）。
- **跨进程剪贴板**：复制同时写系统剪贴板（自定义 MIME + `kb://` 文本兜底），在别处复制、回这里粘贴也能认；
  另有「复制路径」把 `kb://` 串交给外部应用。
- **与系统文件系统换手**：从系统拖入文件（浏览器走 HTML5 drop、桌面走 Tauri 的 drag-drop 事件 +
  `kb_import_path`）、拖出（Chromium 的 `DownloadURL`，字节已在缓存里的图片才给）、
  「导出到本地」（`kb_export_file` 落「下载/Rein」）。
- **断点续传**：批量操作取消后，未完成的条目留在队列里，进度条上出现「继续未完成」，
  从断掉的那一条接着走（已完成的不重做）。粒度是条目——工作区文件是整行写入，条目内分块续写没有意义。
- **上下文菜单**：按选择、位置与能力动态生成；不可用的项带原因（如「删除（系统文件随应用版本更新，不可修改）」）。
- **回收站**：`kb_trash*` 五个命令；删除只是一次 `trashed_at` 标记 + 路径挪进 `回收站/{id}/…`，
  于是原路径立刻腾空（可以马上重建同名文件），恢复时若原路径被占则自动让位（`-v2`）。
  `回收站` 不在任何已知根目录里，加上派生 / 索引对账 / 注入 / 列举四处都过滤 `trashed_at IS NULL`，
  AI 与检索都看不见回收站里的东西。
- **两种删除的边界**：**UI 删除一律进回收站**（可撤销）；AI 的 `delete_note` 仍是硬删
  （模型没有「恢复」这个动作，留一个它管不了也看不见的中间态只会让工作区越来越脏）。
- **操作队列**：批量操作串行执行、有进度、可取消、逐条报告失败（部分成功也说清楚），
  完成后刷新目录并按 id 保留选择与滚动位置。
- **危险操作两步确认**：「彻底删除 / 清空回收站」第一次点只是「上膛」（菜单标签变成 `… · 再点一次确认`
  并弹一条提示），6 秒内的第二次点击才真的执行 —— 不可逆动作不该一点即走。

### 5.3 实现分层（`src/files/*` + `src/components/files/*`）

| 层 | 文件 | 职责 |
| --- | --- | --- |
| 数据模型 | `files/types.ts` | `FileItem`（稳定 id + 元数据 + 权限 + 能力）与 `ItemViewState`（选择 / 焦点 / 剪切 / 拖拽 / 编辑）**分离** |
| 视图模型 | `files/provider.ts` | `IFileSystemProvider`（本目录列举 + 原子操作 + `capability()` 能力声明）；本地实现 `kbProvider`；未来云 / 网络 / 压缩包 provider 只需换实现 |
| 排序分组 | `files/sort.ts` | 自然排序（`Intl.Collator` numeric）、分组、过滤、名称校验、时间/体积格式化（纯函数） |
| 选择 | `files/selection.ts` | Set 存 id + 锚点范围选择 + 键盘移动 + `prune`（刷新后保留仍存在的选择） |
| 操作队列 | `files/opQueue.ts` | 命令化：串行、进度、协作式取消、逐条失败；不认识具体操作 |
| 剪贴板 | `files/clipboard.ts` | 复制 / 剪切（**延迟渲染**：只记引用，粘贴时才读写） |
| 缩略图 | `files/thumbs.ts` | 异步 + LRU + 并发上限 |
| 虚拟滚动 | `files/virtualRows.ts` | 变高行的窗口化渲染 |
| 组件 | `components/files/*` | `FileExplorer`（编排：导航 / 快捷键 / 拖放 / 菜单 / 进度）、`FileRow`、`FileTile`、`FileIcon`、`OpQueueBar` |

约束：**组件不直接读写 `kb_*` 命令**（除 Explorer 里的导入与回收站批量动作），
一律经 provider；UI 不判断「能不能做」，只问 `provider.capability(item, action)`。

### 5.4 UI 规范（强制，`docs/STANDARDS.md` §4 + `tokens.css`）

- 颜色、圆角、阴影、字号、时长、缓动**只引用令牌**（`--surface*` `--accent` `--text-1..3` `--line*` `--radius-*` `--fs-*` `--dur-*` `--ease-*`），**禁止魔法值**。
- 语义色只担语义：可写 = `--accent`；锁定 / 系统 = `--text-3` + `Lock` 图标；危险操作 = `--danger`（仅删除确认态）。
- 图标按钮 `.hdr-btn` 规格 + `aria-label`（必填）；可点元素带 `:active` 按压反馈（全局基线与 `.pressable`）。
- 动效遵守 ARCHITECTURE §5：默认标准曲线、进出同路径、`prefers-reduced-motion` 兜底；长列表不做逐项 stagger。
- 暗色模式跟随 `prefers-color-scheme`（令牌已换肤，组件不得自定义色值）。
- 桌面工作台（≥ `DESKTOP_MIN`）：内容上限 `--frame-max-wide`，hover 态包在 `@media (hover: hover)` 内；移动端最小触控目标 44px。
- 不新增色系、不重做既有视觉语言：与本项目既有组件保持同一套 `-soft` 底 + 深色前景的配对方式。

## 8. 验收

- **数据**：新建一条视频 / 语音 / 文件 → 数秒内在文件树可见，AI 能 `search_knowledge` / `read_knowledge` / `glob_knowledge` 到；日程备注可被检索命中。
- **模态**：同一节点请求 text / audio / video / image——可用时返回本体引用，不可用时降级文本并带 `degraded` 标注；未转写音频不报错、不空转。
- **分类**：新文件落 `未分类数据/` → AI 归类进领域目录并留 `kb_fs_moves` 审计；用户 pin 后 AI 不再移动；投影区写入被拒。
- **注入**：系统提示词 + 用户记忆每轮全量进入提示词；超预算按优先级截断并注明。
- **UI**：AI 页左上角入口可达；管理器在浅色 / 暗色、移动 / 桌面四种组合下合规（截图为准）；`scripts/e2e-kb.mjs` 增补对应断言通过。
- **文件管理器 v2**（`scripts/e2e-ai-workspace.mjs` F 段）：元数据落库并进列表（注释只传标记）、列注册表、
  冲突「保留两者」按 asName 落盘、框选模块、压缩包列条目与选择性解压、画廊/分栏视图渲染、
  断点续传取消后剩余条目可继续、批量重命名面板实时预览。
- **文件管理器**（`scripts/e2e-ai-workspace.mjs` E 段）：一层列举带完整元数据；删除后从浏览视图消失但仍在回收站清单、
  原路径立刻腾空、恢复时让位不覆盖、目录连子树一起走；改名保住本体节点的扩展名、目录不被补 `.md`；
  彻底删除与清空；UI 侧虚拟列表挂载、方向键选择 + Shift 扩选 + F2 就地改名 + Esc 取消。

### P2 里与文件管理器相关、明确**没做**的部分（留给后续）

- **真·缩略图缓存**：现在只在会话内内存缓存（LRU 120 条），没有落盘缓存；也没有服务端解码
  （加 `image` crate 会给四端交叉编译添依赖）。上百张图的大目录反复进出仍会重复解码。
- **外部拖入 / 拖出**：内部拖放（移动到 / 复制到目录、拖到回收站、拖到面包屑）已实现；
  从系统文件管理器拖文件进来要走 Tauri 的 drag-drop 事件，本期没接（导入仍走「导入文件」按钮）。
- **多列排序**：列可增删、点列头可排序，但仍是单列排序（多列排序要重做列头交互与偏好存储）。
- **悬停自动展开文件夹**：拖到文件夹上停住不会自动进入（要再点一下）。
- **自定义拖拽图像与数量徽章**：拖拽时用浏览器的默认拖影。
- **拖出到系统**只对「字节已在缓存里的图片」走 Chromium 的 `DownloadURL`；其余走「导出到本地」。
- **条目内分块续传**：断点粒度是条目（工作区文件是整行写入）。
- **标签 / 评分 / 注释**：元数据只到系统自有字段，没有扩展属性或 sidecar 文件。
- **插件扩展点**：provider 抽象已留好（换云 / 网络 / 压缩包 provider 不用改上层），
  但列提供者、预览 provider、属性页 provider 这些更细的扩展点还没定义。
