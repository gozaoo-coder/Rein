> AI 虚拟工作区 = 全量数据统一编目成的**一棵虚拟文件树** + **模态层** + **AI 自主分类** + **固定注入区** + **自研文件管理器**。
>
> **落地状态（2026-09-19）**：P0 + P1 已实现并通过验收（Rust 单测 104 项、浏览器 e2e 两套：`scripts/e2e-ai-workspace.mjs` 41/41、`scripts/e2e-kb.mjs` 81/81）。
> 实现细节已回写 `docs/kb-vfs.md`（AI 运行时读到的 `规范/知识库规范.md` 就是它）与本文件；**本文档不播种进知识库**，只作为需求映射与后续演进的依据。
> 尚未实现（P2）：关键帧 OCR / 图片视觉描述、`video_memo` 独立来源（视频目前以多模态文件节点 + 转写降级接入）、目录结构自适应重排。

## 1. 数据模型：一切数据皆文件

### 1.1 三律（不可违反）

1. **真源唯一**：每类数据有一张源表。工作区只做编目投影，不产生第二份真源；
2. **派生只读**：投影文档由源表派生，重放即覆盖。要改内容 → 改源数据或走对应命令，不许直接改 `kb_docs`；
3. **本体与文本分离**：二进制本体（音频/视频/图片/文件）**绝不进索引正文**，只登记引用与元信息（沿用现约束，有单测硬断言）。

### 1.2 来源清单

| 域 | source_type | 状态 |
| --- | --- | --- |
| 日程（含备注、子任务） | `todo` | 已有（备注在正文里，可检索） |
| 日程附件 | `todo_attachment` | 已有（仅编目）→ v2 升级为「本体 + 模态」 |
| 对话 / 消息 / 消息附件 | `chat` `chat_message` `chat_attachment` | 已有 |
| 语音纪要 | `voice_memo` | 已有（文本 + 音频本体经模态层可取） |
| 视频 / 通用文件 | `note`（多模态节点，`kb_files.kind='multimodal'`） | 已接入：`kb_media_write` 落本体 + 描述/转录文本模态；**不建独立 `video_memo` 源表**（没有原生录制入口时，它只会是一张空表） |
| 运动 / 课程 / 饮食 / 体测 / 食物 / 方案 / 菜单 | 各自 | 已有 |
| 记忆 / 笔记 / 上传文档 | `memory` `note` | 已有 |
| 记账 / 画像 | `ledger` `profile` | P2 评估（表格化数据，编目价值待验证） |

新增一类数据 = 固定五步（见 §7），**漏一步视为不可合并**。

### 1.3 索引范围（要求 3 后半）

- 进 FTS + 向量的：**text 模态**，以及**可派生出 text 的模态**（转写 / 字幕 / OCR / 视觉描述）。
- 不进索引的：音频/视频/图片/二进制的本体字节，只存元信息（mime、字节数、时长、宽高）。
- 派生文本的来源在命中结果里标注：`modal:"derived"` + `derivedFrom:"audio" | "video" | "image"`，让 AI 知道「这句话来自转写，不是用户原话」。

## 2. 模态层：一个文件，多种模态（要求 2）

### 2.1 概念

一个**逻辑文件**（树上一个节点）= 一组**模态表示**。同一件事的文本、音频、视频、截图不是四个文件，而是一个节点的四种模态：

```
纪要/2026-09-19/晨会-42/          ← 逻辑文件（多模态目录）
├── 纪要.md        text   （转录 + 要点；可被检索/嵌入）
├── audio.wav      audio  （本体；duration 32:10）
├── video.mp4      video  （本体；可选）
└── 白板-12m.png   image  （关键帧 / 截图）
```

数据模型（v2 新增，落库）：

- `kb_files` 扩展：`kind`（`text` | `multimodal`）、`pinned`、`classify_state`（`inbox` | `filed` | `manual`）；
- `kb_assets`（新）：`(id, file_id, modal, mime, storage, ref, bytes, duration_ms, width, height, transcript_state, derived_from, created_at)`；`storage` ∈ `inline`（小文本）/ `fs`（应用数据目录下的相对路径）。

### 2.2 模态与降级链

| 请求模态 | 可用时返回 | 不可用时降级 | 返回标注 |
| --- | --- | --- | --- |
| text | 文本（L0/L1/L2 分页照旧） | — | — |
| audio | 本体引用（mime / duration / 播放句柄） | 转写文本 | `degraded:"text"`，原因（`未转写` / `无音轨`） |
| video | 本体引用（mime / duration / 关键帧清单） | 音轨转写 → 文本 | 同上 |
| image | 本体引用 | 视觉描述 / OCR 文本 | 同上 |
| 其他 binary | 本体引用（导出 / 外部打开） | 文件名 + 类型 + 体积描述 | 同上 |

规则：**降级永远发生，不许失败**；任何读取结果都带 `modalities[]`（该节点实际可用的模态）与 `degraded` 说明——AI 必须能判断「拿到的是不是原件」。

### 2.3 访问与产出

- **读**：`read_knowledge` 增加 `modal` 参数。本体不走 base64 进上下文，而是返回**引用对象**（`assetId / path / mime / duration`），需要展示时由前端渲染。
- **产出**：AI 生成的多模态产物（纪要、朗读音频、录屏）走 `write_modal`：先落本体，再写文本模态，节点一并登记；**没有文本模态的产物必须补一段描述正文**，保证可检索。
- **输出协议**：`{"kind":"chat","text":"…","modals":[{assetId, modal, mime, duration}]}`，前端渲染音频条 / 视频播放器 / 图片查看器；不支持渲染的模态给「导出」入口。

### 2.4 转写状态机

`none → pending → done | failed`。`pending / failed` 时：检索只吃已有文本模态；对 audio/video 请求明确降级并给可操作提示（「转写尚未完成，可稍后重试」），**不报错、不空转**。

## 3. 目录治理：AI 主动分类（要求 3）

### 3.1 默认目录（目标态）

```
/系统提示词/          # 系统只读 · 代码播种 · 全量注入
/用户记忆/            # 可写 · 固定路径 · 全量注入
    角色设定.md
    全局规范.md
/规范/                # 系统只读（kb-vfs.md 播种，现有）
/日程/ /运动/ /饮食/ /体测/ /课程/ /食物/ /方案/ /菜单/ /对话/ /附件/ /记忆/   # 应用投影（派生只读）
/语音/                # 新增：语音本体 + 转写派生（原 纪要/ 并入）
/视频/                # 新增：视频本体 + 转写 / 字幕派生
/文档/                # 上传文档全文归档（现有，可写）
/笔记/                # 手写笔记（现有，可写）
/未分类数据/          # 收件箱（可写）：新内容先进这里，再由 AI 归类
```

### 3.2 四区与写权限

| 区 | 目录 | 可写 | AI 可整理 |
| --- | --- | --- | --- |
| 系统区 | `系统提示词/` `规范/` | ✗ | ✗ |
| 记忆区 | `用户记忆/` | ✓（固定路径） | 仅改内容，不移动 / 改名 |
| 投影区 | `日程/` `运动/` `饮食/` … `记忆/` | ✗（派生文档） | ✗（要改就改源数据） |
| 知识区 | `笔记/` `文档/` `语音/` `视频/` `未分类数据/` + 投影区下的用户子目录 | ✓ | ✓（建目录 / 移动 / 改名 / 打标） |

**保留区规则**：投影文档的路径段（`{日期}/`、`-{id}` 后缀）为保留命名；`kb_files` 写入与之冲突时自动加后缀，**绝不覆盖派生文档**。

### 3.3 分类引擎

- **触发**：① 新文件落 `未分类数据/` → 会话结束时批量归类；② 用户显式要求（「整理一下」）。
- **工具**：`classify_move`（移到目标目录）、`mkdir`、`pin`（钉住，AI 不再移动）、`tag`。
- **规则**（写进系统提示词与工具描述）：
  1. 只动知识区；投影区只读；
  2. 结构约束：深度 ≤ 4、同级条目 ≤ 50、命名走 `sanitize` 同规、单次批量 ≤ 200；
  3. **防抖**：同一文件 24h 内不再自动移动；按内容归类，不按时间瞎挪；
  4. **用户优先**：用户手动放置 / 钉住的，AI 不得覆盖；一切移动写 `kb_fs_moves` 审计（谁 / 何时 / 从哪到哪 / 为什么），可整批撤销；
  5. **结构调整**（重命名 / 合并目录）必须留审计且可撤销，一次会话最多一次。
- **脚手架**：不预建空目录；默认分类目标是既有的领域目录（运动 / 饮食 / 日程 / …），确实无处可放才新建目录。

### 3.4 全量注入区（要求 3 后半）

| 注入项 | 来源 | 时机 |
| --- | --- | --- |
| 系统提示词 | 代码静态段（工具协议 / 输出协议）+ `系统提示词/*.md`（按文件名排序拼接） | 每轮 |
| 用户记忆 | `用户记忆/*.md` 全文 | 每轮 |
| 认知块（长期记忆） | `kb_cognition()`（现有实现，TTL 60s） | 每轮 |
| 其他所有内容 | 检索 / 工具按需 | **不注入** |

- **预算**：注入区总长 ≤ 12,000 字符（建议值，可配置）。超限按优先级截断：系统提示词 > 角色设定 > 全局规范 > 其他，并在提示里注明「有内容被截断」——让 AI 主动去读，而不是装作没这回事。
- **实现衔接**：`buildChatSystemPrompt()` 的静态段改为「读 `系统提示词/` + 拼接」，读结果按 mtime 缓存；`用户记忆/` 缺失时静默跳过（沿用 `cognitionForPrompt` 的容错原则：注入失败绝不阻塞对话）。

## 4. 检索

- 范围：§1.3 定义的文本模态与派生文本；三档模式（keyword / local / cloud）、RRF 融合、L0/L1/L2 分页全部沿用。
- 索引来源开关（`sources_enabled`）增加 `video_memo` 等新来源，默认开启。
- 命中结果区分「原文」与「转写」：转写标注 `derivedFrom`，避免 AI 把 ASR 文本当用户原话引用。

## 5. 文件管理器（要求 4）

### 5.1 入口

- AI 页 `PageHeader` 的 `#lead` 槽（**左上角**）新增文件按钮：`Folder` 图标、`.hdr-btn` 规格（38px 圆形、`--surface` 底、`--shadow-card`）、`aria-label="文件"`。
- 点击 → 文件管理器（建议路由 `/ai/files`，升级现 `FileLibraryPage.vue`；`/ai/knowledge/files` 保留为别名/重定向）。
- **自研、不调外部**：只经 `kb_*` 命令访问虚拟文件系统，不读物理路径、不唤起系统文件管理器。

### 5.2 功能面

- **浏览**：面包屑 + 目录下钻 + 命名空间网格 + 文件名/路径搜索；空目录也要可见。
- **预览**：text（Markdown 渲染 + L2 分页「继续加载 / 一次读完」）、image（缩放）、audio（播放条）、video（播放器）、binary（元信息 + 导出）。
- **文件信息**：路径、来源类型、模态清单、大小 / 时长、索引状态、分类状态、可写 / 只读 / 系统锁。
- **操作**：新建 / 编辑 / 重命名 / 移动 / 删除（仅知识区）、pin、批量移动；每个操作 = 一条 kb 命令。

### 5.3 UI 规范（强制，`docs/STANDARDS.md` §4 + `tokens.css`）

- 颜色、圆角、阴影、字号、时长、缓动**只引用令牌**（`--surface*` `--accent` `--text-1..3` `--line*` `--radius-*` `--fs-*` `--dur-*` `--ease-*`），**禁止魔法值**。
- 语义色只担语义：可写 = `--accent`；锁定 / 系统 = `--text-3` + `Lock` 图标；危险操作 = `--danger`（仅删除确认态）。
- 图标按钮 `.hdr-btn` 规格 + `aria-label`（必填）；可点元素带 `:active` 按压反馈（全局基线与 `.pressable`）。
- 动效遵守 ARCHITECTURE §5：默认标准曲线、进出同路径、`prefers-reduced-motion` 兜底；长列表不做逐项 stagger。
- 暗色模式跟随 `prefers-color-scheme`（令牌已换肤，组件不得自定义色值）。
- 桌面工作台（≥ `DESKTOP_MIN`）：内容上限 `--frame-max-wide`，hover 态包在 `@media (hover: hover)` 内；移动端最小触控目标 44px。
- 不新增色系、不重做既有视觉语言：与本项目既有组件保持同一套 `-soft` 底 + 深色前景的配对方式。

## 7. 接入清单（新增一类数据的固定动作）

1. 源表迁移 + `kb_dirty` 触发器（`db.rs`）；
2. `source.rs` 派生分支 + `build_path` 路径规则；
3. `SOURCE_TYPES` / 类型定义 / 索引来源开关；
4. 有本体的登记 `kb_assets`（模态 + 转写状态）；
5. 单测（路径净化 / 保留区冲突 / 模态降级 / base64 不泄漏 / FTS 一致性）与 e2e 断言。

**门槛**：任何新增数据表若未接入工作区，视为未完成。

## 8. 验收

- **数据**：新建一条视频 / 语音 / 文件 → 数秒内在文件树可见，AI 能 `search_knowledge` / `read_knowledge` / `glob_knowledge` 到；日程备注可被检索命中。
- **模态**：同一节点请求 text / audio / video / image——可用时返回本体引用，不可用时降级文本并带 `degraded` 标注；未转写音频不报错、不空转。
- **分类**：新文件落 `未分类数据/` → AI 归类进领域目录并留 `kb_fs_moves` 审计；用户 pin 后 AI 不再移动；投影区写入被拒。
- **注入**：系统提示词 + 用户记忆每轮全量进入提示词；超预算按优先级截断并注明。
- **UI**：AI 页左上角入口可达；管理器在浅色 / 暗色、移动 / 桌面四种组合下合规（截图为准）；`scripts/e2e-kb.mjs` 增补对应断言通过。
