首屏放什么，其余从哪进

生效态页面的 visitor 目标是 Operate：用户每天打开这页只为回答一个问题——「今天我该做什么，还差什么」。 所以首屏只放「今天的行动 + 打卡确认」，一切「调整、设置、说明」都降级为入口； 每个入口按 使用频率 × 是否需要输入 × 是否不可逆 三个维度，落进内联 / 抽屉 / 菜单 / 二级页四种容器。 左侧 mock 可交互：打卡、展开状态条、打开更多菜单与各抽屉均可点。

1首屏只放「今天的行动 + 确认」

判定标准：用户不做就要亏的（行动）、做完成就立刻有反馈的（确认）进首屏； 静态参数、回顾图表、低频操作一律让位。方案概要从原来 1/4 屏的头卡压缩成一行状态条， 参数详情（BMR/TDEE 等）收进展开区——想看的人多一次点击，不想看的人永远不用滚过它。

内容去留理由
方案状态条（目标·档位·第N周）首屏 · 一行上下文锚点。回答「我在哪」，一行讲完；点开才见参数详情
三环 + 三条进度首屏还差什么的答案，与主页三环同源，不新造隐喻
今日训练 +「开始」首屏 · 主确认今天的头号行动；完成后原位变「已完成」（mock 可点）
下一餐 +「记一笔」首屏 · 次确认打开智能添加并预选本餐次，一天重复 N 次的微打卡必须零跳转；明细只在菜单卡一处
BMR / TDEE / 缺口等参数状态条展开区静态数字，生成后极少变；不配占首屏
周期地图 · 体重航道 · 演进图下滑即达回顾/趋势区，服务「坚持感」而非「行动」，不值得挤占首屏

3组件选型准则

四种容器各管一件事，判定问题只有三个：多常用？要输入吗？可逆吗？

内联
天天发生的微动作。零跳转成本，按钮就是界面本身。 训练打卡 · 记一笔 · 换一批 · 点格子切聚焦日
抽屉 SheetModal
要输入或要专注读，但需要保留上下文的中低频操作。从底部升起、完事即关，Apple sheet 曲线； 一次性大确认（启用方案 / 应用调整）也走抽屉——打断感与操作重量成正比。 手动调参 · AI 复盘 · 科学依据 · 启用确认 · 采购清单
ActionSheet 菜单
低频 + 不可逆 / 一组平级的去向选择。收纳在「⋯」里不占版面；危险项红字 + 二次确认。 归档 · 删除 · 换档重建 · 成绩单入口
二级页
长内容、沉浸式、或需要自己的返回栈。进去会停留一段时间的才配一个页面，否则都是对页面的稀释。 课程详情（开始训练）· 结营成绩单 · 食谱库 · 个人约束向导

对照现状的差异：本轮已把「下一餐」并入驾驶舱、罗盘与全天菜单合并、地图聚焦摘要删除、操作区 2×2 网格化； 这份交互稿在其上再推进一步——头卡压成状态条、归档/删除收进「⋯」菜单（页面下部文字链保留为快捷路径）、 参数详情降为展开区。逐项落地时可独立提交，互不依赖。
