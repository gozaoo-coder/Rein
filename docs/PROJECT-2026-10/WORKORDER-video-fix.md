## 任务

按审核意见**逐条修**，直到被驳回的爆点能通过复审。分两类：

### A. 系统性（对所有 02–29 的场景都做一遍）

1. **统一标题带**：审核反复指出有的镜头有「眉标 + 场景标题」、有的没有，
   导致相邻爆点之间像硬切。请在 `_kit.js` 里加一个 `head()` 帮助函数
   （eyebrow 小字 + 56–72px 场景标题，位置全片一致，例如左对齐 x=176 / 眉标 y=150 / 标题 y=208），
   并让**每一个**场景都用它 —— 标题文案自己写，与爆点内容对得上，不许写工程词。
2. **打破「居中大标题 + 三列等高白卡」**：审核在 10-recipes / 16-plan / 01-pillars 三处点名，
   说这正是设计简报的反例。改成**非对称版式**（如左列选项 + 右侧大面板，或选中项放大上浮、
   其余降饱和下沉）；不要再出现三张等宽等权卡横排。
3. **卡片要有玻璃质感**：审核指出 10-recipes / 16-plan 的卡是平涂白、没有受光边。
   统一走 `var(--glass-*)` 那套（顶部内高光 + 受光边 + 光学层），别用纯 `--surface` 顶着。
4. **内容要撑满、不要骨架感**：11-todo 的时段槽、四象限，23-apis 的右栏，都是「有线框没内容」。
   给真实条目文本；空时段收掉，不要用空灰条撑版面。
5. **色彩配额**：15-score 的 86% 与「优秀」用了绿色文字 —— 数值与正文一律中性色
   （`--text-1/2`），色相只留在图标 / 色点 / 进度条与图表 / 类型字章上。全片自查一遍。
6. **不要跑版**：任何元素不得越出它所在卡片的圆角边界（22-update 的印章、23-apis 的最后一行）。
   卡片按内容撑高，落位动画必须在卡内结束。
7. **尺度**：内容区 1280–1600px，正文 24–30px，标题 56–72px。25-motion 的药丸只有 ~900px、
   blob 只有 50px —— 放大到能撑住整幅。
