## 一、现状盘点（代码调研结论）

### 1.1 数据层：时间盒结构已经具备

`src-tauri/src/modules/todo/models.rs` 的 `Todo`：

| 字段 | 说明 | 对新设计的意义 |
|---|---|---|
| `date` | `YYYY-MM-DD`，null 即收件箱 | 「未安排池」的判定依据 |
| `start_min` | 距 00:00 分钟数 | 有值 = 时间轴块（已有约定 3） |
| `duration_min` | 时长 | 块高度，即时间盒 |
| `category` | general/workout/health/study/work | 块语义色（`--cat-*` tokens 已有） |
| `priority` | 0 普通 / 1 重要 / 2 紧急 | 详情 chip |
| `status` | todo/doing/done | 过块变淡 + 删除线 |
| `program_id` | 来源健康方案 | 方案日程一等公民、改期回写引擎 |

**关键结论：日程就是待办**——`program_schedule_replace`（`src-tauri/src/modules/program/commands.rs:159`）把方案日程事务化地写成带 `date + start_min + duration_min` 的 todos。数据上不存在"待办系统"与"日程系统"两张皮，缺的只是把这些能力组织成一个**规划界面**。

### 1.2 明确缺失（`docs/ARCHITECTURE.md:153` 自述 + 调研确认）

- 无重复规则、无子任务（架构文档明确写"待办无重复规则、无子任务"）
- 无周视图（VirtualTimeline 是连续数轴回看，不是 7 列规划）
- 无"规划动作"：VirtualTimeline 只读浏览 + 点击完成，不能添加、拖拽改位、改期
- 无 AI 排程：AI 只能"生成草稿"（SmartAddSheet），不能"安排已有事项"
- 无每日规划仪式、无周回顾
- 三条时间轴各看各的：HomeSpine（餐次+待办）、桌面 DaySpine（体重/运动/番茄/收支）、VirtualTimeline（待办回看），健康事件与待办从未同轴

### 1.3 可复用的既有资产

`list_all_todos` 排序契约、`update_todo` 全量更新（拖拽改位零新增命令）、SheetModal 三档抽屉、wbar 五槽位停靠、pi-ai 前端 Agent（`buildAppAgentTools`）、`--cat-*`/`--fs-*`/`--ease-*` 全套 tokens、DesktopRail + Inspector 三窗格壳。

## 二、市场对比

### 2.1 格局分层（2026）

| 层 | 代表 | 核心逻辑 | 对健康数据的感知 |
|---|---|---|---|
| 任务深度型 | Todoist、Things 3、Microsoft To Do | 捕获/组织/清空 inbox | 无 |
| 全能型 | TickTick(滴答清单)、Any.do | 任务+日历+番茄+习惯大满贯 | 无 |
| 规划仪式型 | Sunsama、Akiflow、Morgen | 手动时间盒 + 每日规划 + 周回顾 | 无 |
| AI 自动排程型 | Motion、Reclaim.ai、Skedpal | 算法围绕日历自动占块 | 无 |
| 日历优先 | Apple 日历/提醒事项、Fantastical、Structured | 时间轴/日视图为第一界面 | 无 |
| 工作区 | Notion、飞书 | 数据库自由度 | 无 |

### 2.2 关键单项对照

| 能力 | Todoist | TickTick | Things 3 | Sunsama | Motion | Rein 现状 | 提案后 |
|---|---|---|---|---|---|---|---|
| 自然语言捕获 | ★★★ | ★★ | ★ | ★ | ★★ | ★★（AI 草稿） | ★★★（+时间解析） |
| 时间盒/拖拽排程 | ★（付费日历视图） | ★★ | ✗ | ★★★ | ★★★（全自动） | 数据有、UI 无 | ★★★ |
| 每日规划仪式 | ✗ | ✗ | ✗ | ★★★ | 部分 | ✗ | ★★ |
| 周视图 | ★ | ★★ | ★ | ★★ | ★★ | ✗ | ★★ |
| 重复任务 | ★★★ | ★★★ | ★★ | ★ | ★★ | ✗（文档明示） | ★★ |
| 子任务 | ★★★ | ★★★ | ★★★ | ★ | ★★ | ✗（文档明示） | ★★ |
| 周回顾报告 | ✗ | ✗ | ✗ | ★★★ | ✗ | ✗ | ★★（健康关联） |
| AI 读取身体状态排程 | ✗ | ✗ | ✗ | ✗ | ✗ | ✗ | **★★★（独有）** |
| 本地数据/隐私 | 云 | 云 | 本地+iCloud | 云 | 云 | **本地 SQLite** | 本地 |
| 价格 | $4/月 | $3/月 | 买断 ¥398 | $16/月 | $19/月 | 免费 | 免费 |

### 2.3 差异结论

1. **断层**：通用待办工具里，训练课和餐次只是普通色块；健康 app（MyFitnessPal 类）里又没有真正的日程与待办。两边没人打通。
2. **规划深水区全是云端订阅**：Sunsama/Motion/Reclaim 把"时间盒 + 仪式 + AI 排程"做成了 $16–19/月 的云端产品，且没有一个读取你的睡眠、训练负荷、恢复状态。
3. **Rein 的牌**：`日程 = 待办` 的数据统一（program_id 血缘）、本地隐私、AI 前端直连零服务器成本——这三点是竞品结构上做不到的。
4. **Rein 的欠账**：重复、子任务、周视图、规划动作——恰是竞品十年的基本功，必须补齐，否则"独有优势"没有载体。

**一句话定位：Rein 是唯一能用「你昨晚睡了多久、今天训练负荷多大」来安排你一天待办的产品——健康的日程才叫生活规划。**

## 三、设计方案：「今日画布 Day Canvas」

### 3.1 核心概念

把**未安排池 + 可规划时间轴 + 健康事件 + 方案日程**熔成一条轴：

- **未安排池**：`date=今天 && start_min 为空` 的待办，横向 chips。这是"待办"与"日程"之间的桥。
- **时间盒**：拖 chips 入轴即成时间盒（数据已支持，仅差手势与落位 UI）。
- **AI 智能排程**：一键把池中待办按「睡眠时长 / 训练负荷 / 已占用时段 / 空档大小」放进空档；结果逐条可拖动微调——遵守既有 L2 契约"AI 建议 → 用户确认 → 落库"。
- **现在线**：分隔"已过去 / 还剩下"，过时未完成块降透明，一键回到现在。
- **方案日程一等公民**：训练/测量块显示 program 血缘，改期/跳过走 `program_schedule_replace` 事务回写，引擎与执行永不脱节。

### 3.2 新功能分期

**P0（画布骨架）**
1. Day Canvas 日视图：列表轨 / 时间轴 / 详情联动（桌面三窗格），手机 = 池 + 紧凑轴 + 三档抽屉
2. 未安排池 + 拖入成时间盒（拖拽改位 → `update_todo`，零新增命令）
3. 现在线强化 + 过时降透明
4. 周视图（7 列甘特式，复用 VirtualTimeline 缩放经验）

**P1（智能与仪式）**
5. AI 智能排程（pi-ai Agent 新工具 `schedule_todos`；输入：todos+空档+睡眠+负荷；输出：建议槽位，确认后落库）
6. 每日规划仪式：今天首次打开的三步引导（回顾昨天 → 勾选要做 → AI/手动落位），60 秒可跳过
7. 自然语言时间解析增强：SmartAddSheet 解析"明早 8 点跑步 30 分钟"→ date/start_min/duration_min/category

**P2（补齐基本功）**
8. 重复规则：轻量 `rec_rule`（每天/每周N weekday/间隔N天/结束条件），**展开为当日 todos 落库**——不改 `list_todos` 契约
9. 子任务 checklist：`subtasks` JSON 列（勾选走现有 `update_todo` 全量更新）
10. 周回顾：完成率 + 按天分布 + 健康关联洞察一句话（复用归档执行报告能力）
11. 提醒通知（Tauri/Android 通知通道）、ICS 日历导入导出（远期）

### 3.3 UI 规范（示例中已体现）

- **布局**：桌面三窗格（列表轨 212 / 画布自适应 / 详情 316），与 DesktopRail/Inspector 壳体融合；手机单列 + wbar。
- **块语言**：语义 tint 背景（`--blue-soft` 族）+ 深色标题，**不用色条**（1px 以上彩色边条是反模式）；done = 0.45 透明 + 删除线（沿用现有）。
- **语义色**：任务蓝 / 训练绿 / 饮食橙 / 测量紫 / 恢复青，全部来自既有 tokens 值域。
- **详情**：桌面右栏联动切换；手机进 SheetModal 三档抽屉（20/40/90）。
- **动效**：一个 authored moment——AI 排程时 chips 依次落位（ease-out 弹性收尾，~560ms stagger）；其余交互动效沿用 `--ease-standard`。
- **wbar**：五槽位保留，AI 槽升为常驻一级入口。

### 3.4 落地路线

| 里程碑 | 内容 | 主要改动点 |
|---|---|---|
| M1 画布 | DayCanvas 组件替换 /todos 主体；池+轴+详情；拖拽落位 | 新组件；`update_todo` 复用；无迁移 |
| M2 智能 | AI 排程工具 + 仪式卡 + NL 时间解析 | `src/ai/tools/` 注册三步；smartGen 增强 |
| M3 补齐 | 重复/子任务/周视图/周回顾 | `todos` 加列（向后兼容）+ 展开逻辑 |
