# 首页 10 套配色方案

> 姊妹产物：`home-color-palettes.html`（可视化画廊，10 套 × 明暗可切，附令牌表与实测对比度）
> 数据源：`palettes.mjs` · 校验脚本：`scripts/colorlab/audit_palettes.py` · 冒烟测试：`scripts/colorlab/smoke_palette_gallery.mjs`
> 全部数值基于 `src/styles/tokens.css` 的现有令牌结构与 `src/pages/HomePage.vue` 的真实布局，**没有新增任何令牌**。

---

## 一、怎么用这份文档

画廊里的每个方案都是**同一个首页布局**换一套令牌值画出来的：状态条三环、今日画布（未安排池 / 时间轴 / 现在线 / 餐次摘要）、查阅文字链、四格工具、悬浮玻璃 Dock。所见即换肤后的效果。

- 顶部**色板按钮**跳转到对应方案
- **亮色 / 暗色**切换整站（每套都有独立的两套值，不是亮色取反）
- **双屏对照**并排看同一套的明暗两版

推荐评审顺序：先在「单栏 · 亮色」过一遍整体气质，再切「双屏对照」看暗色是否与亮色同源，最后回到单屏细看令牌表里的实测值。

## 二、门槛：什么算「合格」

颜色方案最容易翻车的地方是**好看但读不清**。所以这 10 套不是凭手感挑的，每一套的每一档都过了实测（`audit_palettes.py`，与画廊里 JS 算的是同一套公式）：

| 校验项 | 门槛 | 依据 |
| --- | --- | --- |
| 正文 `--text-1` / surface | ≥ 7:1 | 正文长时间阅读 |
| 次要 `--text-2` / surface | ≥ 4.5:1 | 需要读出来的信息放这一档 |
| 三级 `--text-3` / surface | ≥ 3:1 | 补充信息，不承载必读内容 |
| `--accent-strong` / surface | ≥ 4.5:1 | 选中态文字、链接 |
| `--on-accent` / `--accent` | ≥ 4.5:1 | **实底按钮上的文字** |
| 三环两两 ΔE(Lab) | ≥ 20 | 环必须能互相分辨 |
| 每环 / surface | ≥ 3:1 | 环是粗线，3:1 足够 |

**20 组（10 套 × 明暗）全部通过。**

### 过程中修掉的两个现存缺陷

1. **暗色主色压白字只有 3.65:1**。`tokens.css` 暗色块的注释已经承认这是两难：压深到能托住白字（#0a72e0），当图标色压在 #1c1c1e 上就掉到 3.65:1；保持 #0a84ff，图标色达标但白字 3.65:1。一个失败换另一个失败。
   **正解是解耦**：`--accent` 保持 #0a84ff 当图标 / 链接色（4.66:1 不变），`--on-accent` 在暗色档改成深墨色（#04101f 之类）压上去 → 5.24:1。这是 9 套新方案里除「素白」外全部采用的做法。
2. **亮色运动环 2.98:1**，差 0.02 不到 3:1 的线。压到 #569f00 → 3.30:1。

方案 00「原生银」就是带着这两处修正的现行配色，作为对照基准。

### 选型建议

- **想零风险上线** → 00。它与现有 58 份 UI 审查报告逐条对得上，评审时争议最小。
- **常在夜里用** → 01 石墨夜航。暗色在它这儿不是「亮色反过来」，而是独立设计过的一套（画布带蓝味、卡片比画布亮一档）。
- **把 Rein 当工具** → 09 素白。它同时也是「视觉重心」那个问题的参考答案：主色退成黑白后，页面上唯一有色彩的就是三环与状态色，重心自动落到数据上。代价是 Dock 选中态几乎不可见，要靠中性活动底撑。
- **其余七套** 属于气质选择，没有功能差异。

## 四、换肤时必须同步改的地方（易漏清单）

一套配色不只是换 `--accent`。以下位置在现有代码里**硬编码或半硬编码**了颜色，换肤时必须一起走，否则会出现「主色换了但某处还是旧蓝」：

| 位置 | 现状 | 处理 |
| --- | --- | --- |
| `base.css` body 背景 | 径向渐变三段色写死在 CSS 里 | 提成 `--bg-hi` / `--bg-mid` 令牌（本方案已按此给出值） |
| `base.css` 玻璃受光环 | `rgba(255,255,255,…)` 写死 | 暖色系方案（02 暖砂 / 06 柑柠 / 08 落日）需偏暖，否则玻璃在暖画布上显脏 |
| `CanvasTimeline` 块底 | `color-mix(分类色 15%, surface)` | 已经是 mix，改 surface 即自动跟随 |
| `PageHeader` 页头 | 全部走令牌 | 无需改动 |
| 工具格圆章 | 插件层用 `color-mix(--c-*, 12%)` 铺底 + 实色图标 | 已走令牌。实测铺底与卡片面对比只有 1.12–1.22（亮暗都低），**这是正常的** —— 圆章的辨识靠的是里面那枚实色图标，不是这层薄底。换肤时不要为了「让底更明显」去加浓度，那只会得到一块脏印 |
| 记账 15 个分类色 | `--led-*` 写死 iOS 色板 | 换肤时按主色色相重排一版，否则与新主色不同源 |
| 沉浸跑步页 | `--hero-*` 深色剧场 | **建议不参与换肤**：它本来就是独立暗场，与主页主题无关 |

### 暗色配色的额外注意

暗色不是把亮色反相。三件事必须重做：

1. **卡片要比画布亮**。暗色下卡片不是「更暗的块」而是「更亮的块」，否则整屏糊成一片。
2. **`--glass-*` 要重调**。`rgba(40,40,46,…)` 这类值带灰味，落到暖色 / 冷色画布上会显脏。
3. **glass-tab-fill 的浓度不能随便加**。`tokens.css` 注释里记着：这个值是量出来的，0.14 会让选中态文字对比掉到 4.6:1，没有余量。换肤时若要动它，必须重新实测。

## 五、推荐落地路径

1. **先只做暗色的 `--on-accent` 解耦**（方案 00 的修正）。这是一处令牌改动、零组件改动，直接把 3.65:1 提到 5.24:1，是收益最高的一步。
2. **把 body 渐变三段提成令牌**。这是换肤的前置条件，不做的话任何新配色都要动 `base.css`。
3. **选一套做真机验证**。建议 01 或 09 —— 01 验证暗色，09 验证「无主色」下选中态是否还成立。
4. **记账 15 色按新主色重排**。这是工作量最大的一块，但不改就会明显看出是两套系统。
5. 最后再考虑是否开放多皮肤给用户选择。**建议先不做** —— 皮肤多了以后，「视觉重心」这类问题会被放大 N 倍。

## 六、下一步：视觉重心

配色是地基。但从这次评审里已经能看到几个与颜色无关、只靠换色解决不了的问题，留到下一轮：

- 首页有 **5 个视觉焦点**（1486 大数字、三环、今日画布标题、四格工具、悬浮 Dock），彼此没有主次
- 「打开完整画布 7 条未完成 ›」这条**引导用户下一步操作**的信息用 `--text-3`（3.62:1）—— 而 `--text-3` 在 `tokens.css` 里的定位是「补充，不是正文」，凡是必须读出来的都不该放这一档
- 时间轴起止时刻是 **10px 裸值**（`CanvasTimeline.vue` 的 `.bmin`），在 430px 宽屏上是最小字。顺带查出：`src/` 里共 **82 处 `font-size` 没走 `--fs-*` 令牌**（抢课 8px、AI 页 9px 等），与 `docs/STANDARDS.md` 第 37 行「颜色、圆角、阴影、**字号**、时长、缓动只引用 tokens.css 令牌；review 时看到魔法值直接打回」相抵触 —— 字号体系事实上没有守住
- 玻璃 Dock 的选中态只有「底亮一格 + 文字变主色」，在无主色方案（09 素白）下几乎不可见

这些都要等配色定下来、有了一个确定的视觉主色之后再处理 —— 否则是在漂移的基准上做优化。
